Your first workflow in 5 minutes

Want to try it without an AI CLI first? The getting-started guide begins with a small echo workflow and then adds agents, tests and approval.

  1. Install and open Orchevia. The first-run wizard detects git, gh, claude, and codex, and creates your first agent profiles.
  2. Workflows → Samples… → Plan → Implement → Review → Create. A ready-made graph appears on the canvas.
  3. Select any node to configure its profile, prompt, or timeout. Canvas badges flag problems before you run.
  4. Press ▶ Run. Approve the paused gate, inspect per-node output under Runs, cancel anytime. Opening a workflow never runs it.
  5. Go further: generate flows from a goal with ✦ Generate, save reusable Templates, or schedule nightly runs under Automations.

Local-first, by architecture

Your tools, your auth

Orchevia delegates AI work to CLIs you installed and authenticated. It never asks for model API keys.

Your data stays home

Workflows and runs live in a local SQLite database. Orchevia has no telemetry service; the AI CLIs you choose may contact their providers.

Explicit execution

Opening a workflow never executes it. Inspect commands before running; runs are explicit, the active child is stopped on cancel, and authentication stays in your tools. Stored output can contain sensitive data; review it before sharing.

Installation

Orchevia is in beta. The repository and release downloads are private for now and will be public soon. Public installer links will be added here when access opens.

Available platforms are macOS Apple Silicon/Intel and Linux x86_64. macOS builds are unsigned and not notarized. Workflows execute with your user permissions; review generated or imported commands before running.

For contributors with repository access

Contributors with repository access can build from source with Node.js 24+, pnpm 10+, Rust stable, and the platform dependencies in the development guide. 

git clone https://github.com/iazaran/orchevia.git
cd orchevia
pnpm install
pnpm tauri dev

pnpm dev opens the browser demo with a local mock backend; pnpm tauri dev runs real workflows in the desktop app. See the development guide.

Build and contribute

The React editor in src/ talks to a typed backend interface. pnpm dev uses its mock so contributors can work on the UI without launching native processes. The Tauri commands in src-tauri/ delegate execution, validation, scheduling, and SQLite storage to crates/core/.

Start with the development guide, architecture, and workflow schema. Run pnpm check, cargo test -p orchevia-core, cargo clippy -p orchevia-core --all-targets -- -D warnings, cargo fmt --check, and cargo check -p orchevia before opening a PR. GitHub Actions validates applicable frontend, Rust, and Linux desktop changes on PRs. Version tags build Linux, Apple Silicon, and Intel installers; downloads require a successful release and repository access.

Before you start

Do I need an Orchevia account or model API key?

No. Orchevia orchestrates CLIs you install and authenticate yourself. Model access and usage costs belong to those tools and providers. A command-only workflow needs no AI profile.

Does local-first mean everything stays offline?

Workflows and run history live in local SQLite, and Orchevia has no telemetry or hosted worker. Your AI CLIs, GitHub operations and MCP integrations may contact their own remote services.

Can I use my own CLI or repository's test commands?

Yes. Configure a custom CLI profile or a Command node with an executable and separate arguments. Built-in templates are language neutral. You provide the commands, model choices and repository conventions that work in your project.

What happens when a step fails or I cancel?

Inspect per-step errors and partial output in Runs. Workflows can define explicit retries and failure paths. Cancellation stops the active child; it does not undo earlier file edits, commits or remote writes, and child tools may spawn their own processes. Review side effects before rerunning.

Will schedules run with the app closed?

Schedules and watchers need the app running. Opt into background mode to keep it in the system tray when the window closes. Quitting the app or shutting down the machine stops local automation; there is no cloud worker.

Which platforms and limitations should I know about?

The beta targets Linux x86_64 and macOS Apple Silicon/Intel. Windows is not supported. macOS installers are unsigned and not notarized. Execution uses your user permissions without a sandbox. Review imported workflows and stored output before running or sharing them.

Contribute

The repository will be public soon under Apache-2.0. Useful contributions include a workflow recipe, clearer setup guidance, accessibility improvements, or a bug report with the failing step and a redacted log. Start with a small reproducible case and keep the CLI/core/UI boundaries consistent.
