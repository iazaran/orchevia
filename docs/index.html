n8n import & export

Use n8n for SaaS glue. Use Orchevia for code.

n8n is great at connecting hundreds of web services. Orchevia is built for coding agents working in your repositories. Now a workflow can move between them in either direction.

  • Export any workflow as n8n JSON: paste it onto an n8n canvas or import it from a file.
  • Import an n8n workflow: commands, HTTP requests, If nodes, waits, Jira and AI agent nodes become Orchevia steps.
  • Nothing silent: every conversion lists what changed and what has no equivalent.
Orchevia step n8n node Notes
Start + run inputs manualTrigger + set Inputs become fields on a “Workflow inputs” node.
Command, Git, GitHub executeCommand The same git and gh commands, in the same folder.
AI agent executeCommand Calls your local CLI (claude -p, codex exec, …).
Condition if True and false outputs keep their branches.
Approval wait Resumes on its webhook; swap in “send and wait” to approve from chat.
Ticket jira Connect your Jira credentials in n8n.

Workflow generator

Describe the task. Get a graph you can check.

Your own CLI drafts the workflow from a goal, grounded in your repository and its playbook. Orchevia compiles and validates it, lists the risky steps, and shows a preview. Nothing runs until you accept and press Run.

  • Uses your playbook: real test and build commands, not guesses.
  • Safe by construction: no invented tools, credentials or unbounded loops.

Authoring

A graph for inspection. JSON for reuse.

Every workflow is plain JSON you can read, diff and share. Switch between Simple JSON (readable keys) and Advanced JSON (the full definition) in the editor, which colors it and points at the line of any mistake.

  • Templates export as portable JSON with roles, never secrets.
  • Import from Orchevia JSON, a template or an n8n workflow.
  • Run inputs, handoffs and loop bounds live in the file.

Local-first

Your machine, your sign-ins, permissions you can read

No account, no keys

Orchevia calls the CLIs you installed and signed in to. It never asks for a model API key and has no account or telemetry.

Permissions, decided once

Choose whether agents follow their own CLI settings or work without asking, app-wide or per profile. Steps that publish are marked and gated.

History stays local

Workflows, runs and outputs live in SQLite on your machine. Orchevia only asks GitHub for its latest release, and you can turn that off.

Download

Install Orchevia

Free and open source. The links below always point to the latest release. Windows is not supported yet.

macOS Apple Silicon Orchevia-macos-arm64.dmg macOS Intel Orchevia-macos-x86_64.dmg Linux AppImage · x86_64 Orchevia-linux-x86_64.AppImage Linux Debian / Ubuntu · x86_64 Orchevia-linux-x86_64.deb

Debian and Ubuntu: signed apt repository

Add it once, and sudo apt upgrade keeps Orchevia up to date. 

curl -fsSL https://iazaran.github.io/orchevia/apt/orchevia-archive-keyring.gpg | sudo tee /usr/share/keyrings/orchevia-archive-keyring.gpg > /dev/null
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/orchevia-archive-keyring.gpg] https://iazaran.github.io/orchevia/apt stable main" | sudo tee /etc/apt/sources.list.d/orchevia.list
sudo apt update && sudo apt install orchevia

Other Linux: sudo apt install ./Orchevia-linux-x86_64.deb, or chmod +x the AppImage and run it.

macOS first launch

Builds are not notarized yet, so macOS blocks the first launch with a warning that it cannot verify Orchevia. Close the warning, then choose Open Anyway in System Settings → Privacy & Security (System Preferences → Security & Privacy on macOS 12 and earlier), or run: 

xattr -dr com.apple.quarantine /Applications/Orchevia.app

Verify your download

Save SHA256SUMS next to the installer, keep the file names, and look for OK: 

# Linux
sha256sum -c SHA256SUMS --ignore-missing
# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing
Build from source

Contributors can build from source with Node.js 24+, pnpm 10+, Rust stable and the platform dependencies in the development guide. pnpm dev opens a browser preview with a mock backend; pnpm tauri dev runs real workflows in the desktop app. 

git clone https://github.com/iazaran/orchevia.git
cd orchevia
pnpm install
pnpm tauri dev

FAQ

Before you start

Do I need an Orchevia account or a model API key?

No. First Workflow runs with local commands. For AI steps, sign in through each CLI the way its provider expects. Orchevia has no account or model API key field.

Which agents and MCP servers work?

Built in: Claude Code, Codex, Gemini CLI, Google Antigravity CLI, OpenCode and Muse Code. One click through the Custom CLI adapter: GitHub Copilot CLI, Cursor CLI, Qwen Code, Amp, Aider, Goose and Kiro CLI. Any local (stdio) MCP server works; 22 have ready-made setups, and remote servers connect through mcp-remote.

How does Orchevia compare with n8n?

n8n automates web services with hundreds of integrations and a hosted or self-hosted server. Orchevia is a desktop app for coding agents in your repositories: approvals, review rounds, loops, Git and pull requests, with no server. Use both: export a workflow to n8n or import one from it.

What does it cost?

Orchevia is free and open source (Apache-2.0). Your AI CLIs are billed by their providers as usual. Runs show the tokens and the API value a CLI reports; enter your monthly plans in Usage & costs to see what the work cost on them.

Does local-first mean everything stays offline?

Workflows and run history live in local SQLite, and Orchevia has no telemetry or hosted worker. Orchevia itself only asks GitHub for its latest release, and you can turn that off. Your AI CLIs, GitHub operations and MCP servers may contact their own services.

What happens when a step fails or I cancel?

Inspect per-step errors and partial output in Runs. Workflows can define retries and failure paths. Cancelling stops the active step and its process group; it does not undo earlier file edits, commits or remote writes.

Will schedules run with the app closed?

Schedules and watchers need the app running. Background mode keeps it running when the window closes; there is no cloud worker.

Which platforms are supported?

Linux x86_64 and macOS on Apple Silicon and Intel. Windows is not supported yet. macOS installers are ad-hoc signed but not notarized, so the first launch needs Open Anyway. Steps run with your user permissions and are not sandboxed.

Help make Orchevia the best place to run agents

Orchevia is young and maintainer-run. A star helps other developers find it; a template, an MCP setup, a fix or a bug report with a redacted log makes it better for everyone.
