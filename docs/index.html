Workflow generator

Describe the task. Get a graph you can check.

✦ Generate asks your own Claude Code or Codex CLI to draft the workflow. Orchevia validates and compiles the draft into a preview — it never runs it.

  1. Open Workflows → ✦ Generate. Pick Claude Code or Codex and, optionally, a repository: the AI is asked to inspect it without changing anything, so the draft uses your real paths and conventions. It runs with that profile's permissions.
  2. Write the goal like a short spec. Name the agents, the commands that prove it works, where you approve, and which writes are allowed.
  3. Review the preview. Steps, risk categories, setup items and every compiler repair are listed. Ask AI to fix sends blocking problems back for another round.
  4. Accept & edit, then Dry run. The workflow opens on the canvas; test its routing with fixtures before running real tools. 
Read Jira ticket {{input.ticket}} and plan it with Claude, then pause for my approval. Implement it on branch {{input.branch}}, run pnpm test, and have Claude and Codex review the diff in parallel. Fix P0/P1 findings (at most twice), then open a draft PR.

Generation prefers native Agent, Git, GitHub, Ticket, MCP, Condition and Approval nodes; Command nodes cover your own tools. Instructions such as “CLI only” win. ✦ Assist improves or rearranges an existing workflow through the same reviewed preview.

Product tour

Everything a run touched, in one place

Real screens from the desktop app. Edit on the canvas, follow each run step by step, and see what your CLIs reported.

  • Ten node kinds: Start, Command, AI Agent, Condition, Human Approval, Git, GitHub, Ticket, MCP Tool and End.
  • An inspector for every node: profile, prompt with {{variables}}, required tools, session reuse, timeouts and loop bounds.
  • Validation before you run: badges on the canvas, and Simple JSON that stays in sync with the graph.
  • A timeline on one time axis, so parallel reviews and loop visits are easy to read.
  • Output and findings per step, with whether the agent resumed its earlier context.
  • Read-only run snapshots on the canvas, and deliberate recovery of failed runs from their original inputs.
  • Agent attempts, tokens and tool calls by workflow, profile, provider and model.
  • Honest money lanes: CLI-reported API estimates stay apart from the subscription fees you enter.
  • Budgets per run: cap agent attempts or pause at a reported spend estimate.
  • Profiles per role: planning, implementation, fast and deep review, generation — each with its own CLI, model and effort.
  • Any CLI: Claude Code, Codex, or a custom binary that takes the prompt last.
  • Detected on your login shell's PATH, including nvm, fnm, Homebrew and ~/.local/bin.

Safety

Local-first, with permissions you can read

Orchevia passes permission flags on the command line and never edits your Claude Code or Codex settings. You decide once, in setup or Environment, whether agents work without asking; an Agent Profile can still pick its own level:

Use the CLI's settings

No flag is added; your own Claude Code or Codex configuration decides what a step may do. What every profile uses until you choose.

Allowed tools --allowedTools

An explicit Claude Code allow list. Nodes declare the tools they need, and imports and runs warn about anything the profile doesn't grant.

Full access

Bypasses permission checks, for every agent or one profile. Never chosen for you, and a schedule that uses it needs its own trust opt-in.

Refusals fail the step

When headless Claude Code refuses a tool, the step fails with the exact allow rules that would admit it instead of a silent “success”. Codex and Claude text-output profiles report no refusals, so these can't be caught.

Explicit execution

Opening, importing or previewing never runs anything. Cancel and timeouts stop the step's process group on Linux and macOS.

Your data stays home

Workflows and runs live in local SQLite. Your AI CLIs, GitHub and MCP servers may still contact their own services.

Getting started

Your first workflow in 5 minutes

  1. Install and open Orchevia. The setup wizard detects git, gh, claude and codex and creates recommended agent profiles.
  2. Workflows → Samples… → Plan → Implement → Review → Create. A ready-made graph appears on the canvas.
  3. Select any node to set its profile, prompt or timeout. Canvas badges flag problems before you run.
  4. Press ▶ Run. Approve the paused gate, follow each step in Runs, cancel at any time.
  5. Go further: ✦ Generate from a goal, save Templates, or schedule runs under Automations.

Start without any AI

The getting-started guide begins with a one-step echo workflow, then adds an agent, tests, an approval gate and reuse.

Headless Claude Code refuses tools its settings don't allow. If a step reports tools refused, add the listed rules to the profile in one click.

Download

Install Orchevia

Free and open source. The links below always point to the latest release. Windows is not supported yet.

macOS Apple Silicon Orchevia-macos-arm64.dmg macOS Intel Orchevia-macos-x86_64.dmg Linux AppImage · x86_64 Orchevia-linux-x86_64.AppImage Linux Debian / Ubuntu · x86_64 Orchevia-linux-x86_64.deb

Verify your download

Save SHA256SUMS next to the installer, keep the file names, and look for OK: 

# Linux
sha256sum -c SHA256SUMS --ignore-missing
# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing

First launch

macOS: builds are not signed or notarized yet. Run the command below, or open the app once and choose Open Anyway in System Settings → Privacy & Security. 

xattr -d com.apple.quarantine /Applications/Orchevia.app

Linux: sudo apt install ./Orchevia-linux-x86_64.deb, or chmod +x the AppImage and run it.

Build from source

Contributors can build from source with Node.js 24+, pnpm 10+, Rust stable and the platform dependencies in the development guide. pnpm dev opens a browser demo with a mock backend; pnpm tauri dev runs real workflows in the desktop app. 

git clone https://github.com/iazaran/orchevia.git
cd orchevia
pnpm install
pnpm tauri dev

FAQ

Before you start

Do I need an Orchevia account or a model API key?

No. Orchevia orchestrates CLIs you install and sign in to yourself, so AI steps use your existing Claude or ChatGPT/Codex plan and its limits. A command-only workflow needs no AI CLI at all.

What does it cost?

Orchevia is free and open source (Apache-2.0). Usage of your AI CLIs is billed by their providers as usual. Runs show the tokens and any dollar estimate a CLI reports; those estimates are not your subscription bill or remaining quota.

Does local-first mean everything stays offline?

Workflows and run history live in local SQLite, and Orchevia has no telemetry or hosted worker. Your AI CLIs, GitHub operations and MCP integrations may contact their own remote services.

Can I use my own CLI or my repository's commands?

Yes. Add a custom CLI profile, or use a Command node with an executable and separate arguments. Templates are language neutral; you supply the commands, models and conventions that work in your project.

What happens when a step fails or I cancel?

Inspect per-step errors and partial output in Runs. Workflows can define retries and failure paths. Cancelling stops the active step and its process group on Linux and macOS; it does not undo earlier file edits, commits or remote writes, so review side effects before rerunning.

Will schedules run with the app closed?

Schedules and watchers need the app running. Background mode keeps it in the system tray when the window closes. Quitting the app or shutting down the machine stops local automation; there is no cloud worker.

Which platforms are supported?

Linux x86_64 and macOS on Apple Silicon and Intel. Windows is not supported yet. macOS installers are not signed or notarized. Steps run with your user permissions and are not sandboxed.
