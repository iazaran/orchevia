# Support

## Where to get help

- **Documentation**: start with the [README](./README.md), then
  [`docs/`](./docs/) (architecture, workflow schema, security, development).
- **Bug reports**: [open an issue](https://github.com/iazaran/orchevia/issues/new/choose)
  using the bug report template. Include: Orchevia version, OS + version, what you did,
  what you expected, what happened, and relevant (redacted) logs.
- **Feature ideas**: use the feature request template. Check the
  [roadmap](./ROADMAP.md) first — your idea may already be planned.
- **Security issues**: see [SECURITY.md](./SECURITY.md) — do not file public issues.

## Diagnostics

In the desktop app, the Runs screen shows per-node stdout/stderr and exit codes. When
reporting a bug, include the run's node results (remove any secrets first — Orchevia never
needs your tokens).

## Response expectations

Orchevia is early-stage and maintainer-run. We triage issues weekly; pull requests with
tests and a clear description get priority.
